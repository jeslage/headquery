# @headquery/statamic

> **Early development.** headquery is still under development and should not be used in production yet. APIs, generated types and the schema format may change in any 0.x release.

Typed, cacheable client for the [Statamic REST Content API](https://statamic.dev/rest-api).
You keep Statamic's own query vocabulary (filters, sort, fields), written in TypeScript.

```bash
npm install @headquery/statamic
```

```ts
import { createStatamicClient } from "@headquery/statamic";
import "./cms.generated"; // optional: types generated by @headquery/codegen

const cms = createStatamicClient({ baseUrl: "https://cms.example.com" });

const posts = await cms
  .collection("blog")
  .entries()
  .where("title", "contains", "monorepo")
  .sort("-date")
  .limit(10)
  .get();
// GET /api/collections/blog/entries?filter[title:contains]=monorepo&limit=10&sort=-date
```

All reads are plain `GET` requests with deterministic URLs, so browsers, CDNs and proxies can cache them.
Without generated types it works with loose types. Run [`@headquery/codegen`](https://www.npmjs.com/package/@headquery/codegen)
to get autocomplete for collections and fields, and type errors for fields that aren't in `allowed_filters`.

Supported: collection entries, taxonomy terms, globals, navigation trees.

See the [repository](https://github.com/jeslage/headquery) for documentation. MIT licensed.
