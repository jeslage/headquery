# Field types

How the addon maps Statamic fieldtypes to the types that
[`headquery generate`](/codegen/generate) writes:

| Statamic | TypeScript |
| --- | --- |
| `text`, `textarea`, `markdown`, `slug` | `string` (`\| null` unless required) |
| `integer`, `float`, `range` | `number` |
| `toggle` | `boolean` (never null) |
| `date` | ISO `string` |
| `select`, `button_group`, `radio`, `checkboxes` | `HqOption<"a" \| "b">` (`{ key, value, label }`; all `null` when empty) |
| `assets` | `HqAsset` or `HqAsset[]` (`max_files`) |
| `entries`, `terms`, `users` | `HqRelatedEntry`, `HqRelatedTerm`, `HqUser` |
| `grid`, `replicator` | arrays of typed rows/sets (`[]` when empty) |
| `bard` | `HqRichText` (HTML string without sets, blocks with sets) |
| unknown fieldtypes | `unknown` — see [custom fieldtypes](/cms/statamic/custom-fieldtypes) |

## System fields

System fields Statamic adds to every entry, term, global set and asset (`id`, `url`, `status`,
`permalink`, …) come from `HqEntryBase`, `HqTermBase`, `HqGlobalBase` and `HqAssetBase`.
Blueprint fields with the same handle take precedence.

## Filterable fields

Fields listed in `allowed_filters` (see [Getting started](/cms/statamic/getting-started#rest-api))
are marked filterable in the schema. Only those are accepted by `.where()`.

Allowed filters that aren't blueprint fields, such as an entry's `date` or an asset's
`basename` and `folder`, are exported as `systemFilters` and accepted by `.where()` too.
