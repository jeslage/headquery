# Setup

Everything that happens on the Statamic side. For the short path from zero to a typed query,
follow [Getting started](/getting-started/statamic).

## REST API [#rest-api]

headquery wraps Statamic's [REST Content API](https://statamic.dev/rest-api). It is a
Statamic Pro feature and off by default. In the CMS's `.env`:

```dotenv
STATAMIC_PRO_ENABLED=true
STATAMIC_API_ENABLED=true
```

Then enable the resources you want to query in `config/statamic/api.php`:

```php
'resources' => [
    'collections' => [
        'blog' => [
            'allowed_filters' => ['title', 'slug', 'featured'],
        ],
    ],
    'taxonomies' => true,
    'globals' => true,
    'navs' => true,
],
```

- Only enabled resources end up in the schema, and only they can be queried.
- Only `allowed_filters` fields can be used in `.where()`. Statamic answers other filters
  with `422`, and the generated types reject them at compile time.

The API route defaults to `/api` (`statamic.api.route`). If you change it, set `apiPrefix` in
the client and `from.apiPrefix` in the [codegen config](/codegen/config).

## Install the addon [#addon]

```bash
composer require headquery/statamic
php artisan vendor:publish --tag=headquery-config   # optional: config/headquery.php
```

The addon supports Statamic 5 and 6 on PHP ≥ 8.2. It only exports the schema; it doesn't
change how the REST API answers.

`config/headquery.php` holds the schema endpoint settings and mappings for
[custom fieldtypes](/cms/statamic/custom-fieldtypes).

## Export the schema [#export-the-schema]

When the frontend lives in the same repo, export the schema to a file and point codegen at it:

```bash
php please headquery:schema --out=schema.json
```

Run it again whenever you change a blueprint or `config/statamic/api.php`.

## Schema endpoint [#schema-endpoint]

When the frontend lives in another repository, codegen fetches the schema over HTTP
instead. Turn the endpoint on in the CMS's `.env`:

```dotenv
HEADQUERY_SCHEMA_ROUTE=true
HEADQUERY_SCHEMA_TOKEN=a-long-random-token
```

It answers at `GET /api/headquery/schema` (below `statamic.api.route`; the path is
`headquery.schema.path`). In the frontend, set `from: { baseUrl }` in the
[codegen config](/codegen/config) and the same token as `HEADQUERY_SCHEMA_TOKEN`.

After changing `.env` on a server with cached config, run `php artisan config:clear`.

### Security [#security]

<Callout type="info">
  The endpoint is **off by default**. It only answers when both variables are set.
</Callout>

- `404` unless `HEADQUERY_SCHEMA_ROUTE=true` **and** `HEADQUERY_SCHEMA_TOKEN` is set.
- `401` without the correct `Authorization: Bearer <token>`. The token is compared in
  constant time.
- Responses carry an `ETag`. Unchanged schemas answer `304 Not Modified`.

The schema describes your content model (handles, field names and types), not your
content. Treat the token like any other deploy secret anyway.

## Troubleshooting

When the schema can't be loaded, `headquery generate` prints the underlying error and the
most likely cause. All errors and their fixes are listed under
[Troubleshooting](/cms/statamic/troubleshooting).
