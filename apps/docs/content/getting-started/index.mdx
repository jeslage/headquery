# Getting started

Setting up headquery has the same four stages for every CMS:

1. **Prepare the CMS.** Turn on its REST API and install the small headquery plugin that
   exports your content model as a schema.
2. **Install the client and the CLI** in your frontend: one adapter package for your CMS
   (e.g. `@headquery/statamic`) and `@headquery/codegen` as a dev dependency.
3. **Run `headquery init` once.** It writes `headquery.config.ts`, a typed client file,
   `package.json` scripts and env lines.
4. **Run `headquery generate`** whenever the content model changes. It turns the schema
   into TypeScript types that the client picks up.

## Requirements

- Node.js ≥ 20 in the frontend. Node ≥ 22.18 lets the CLI load a `headquery.config.ts`
  directly; on older versions `init` writes `headquery.config.mjs` instead.
- A CMS version supported by its plugin, listed on the CMS's overview page.

## File or endpoint?

The CLI needs the schema of your content model. It can read it from a JSON file the CMS
exports, or fetch it from an authenticated endpoint on the CMS. The CMS guides show both;
[Codegen](/codegen#schema-sources) explains which to choose.
